# WhiteList CRM

REST API для учёта звонков и встреч.

FastAPI + PostgreSQL, всё запускается в Docker.

## Запуск

Нужен только Docker.

```bash
git clone https://github.com/necros2604/whitelist-crm.git
cd whitelist-crm
docker compose up --build
```

- API: http://localhost:8000
- Документация: http://localhost:8000/docs

Таблицы и три менеджера (id 1, 2, 3) создаются автоматически при старте. Файл `.env` не нужен: `DATABASE_URL` уже задан в `docker-compose.yml`.

Остановить: `docker compose down`. Удалить вместе с данными: `docker compose down -v`.

Если пишет `port is already allocated` - порт 8000 или 5432 уже занят. Остановите другой процесс или поменяйте левую часть в `ports` в `docker-compose.yml` (например, `"5433:5432"`).

## Тесты

```bash
docker compose run --rm --build api pytest -v
```

Тесты используют отдельную базу `crm_test`, рабочие данные не трогают.

Обязательные тесты:
- пересечение встреч - `tests/test_meetings.py::test_meeting_overlap`
- граница рабочего дня - `tests/test_rules.py::test_working_hours_boundaries`

## Примеры запросов

`requests.http` - для расширения REST Client в VS Code. Запускайте по порядку сверху вниз на чистой базе.

## Эндпоинты

- `POST /companies` - добавить компанию
- `GET /companies?status=&limit=&offset=` - список компаний
- `POST /calls` - результат звонка
- `POST /meetings` - назначить встречу
- `PATCH /meetings/{id}` - перенести (`{"starts_at": ...}`) или отменить (`{"status": "cancelled"}`)
- `GET /managers/{id}/schedule?date=2026-11-23` - расписание на день

Время передаётся с часовым поясом (`2026-11-23T05:00:00Z`), ответы всегда в UTC.

Ошибки приходят так: `{"error": "manager_busy", "message": "У менеджера уже есть встреча в это время"}`.

## Принятые решения

- Статус компании = результат последнего звонка (`new`, если звонков не было).
- Сначала создаётся встреча, потом звонок `meeting_set` с её `meeting_id`.
- У компании может быть только одна запланированная встреча.
- Дата в расписании - день по Алматы. Отменённые встречи в расписании не показываются.
- Отмена не удаляет встречу, а ставит статус `cancelled`. Отменённую встречу менять нельзя.
- Пересечения и вторую встречу компании запрещает сама база, поэтому одновременные запросы не создадут дубль.

## Что не сделано

- Нет проверки, что встреча не в прошлом.
- При отмене встречи статус компании не меняется.
- Нет эндпоинтов для менеджеров и для просмотра одной встречи.
